# Security policy

## Supported versions

6ixstack is deployed from `main`. Only the latest `main` receives security fixes.

## Reporting a vulnerability

**Please don't report security vulnerabilities through public GitHub issues, pull requests or discussions.**

Report them privately through GitHub's
[private vulnerability reporting](https://github.com/QuinntyneBrown/6ixstack/security/advisories/new)
(the **Security** tab, then **Report a vulnerability**).

Include as much of the following as you can:

- The type of issue, for example cross-site scripting, authentication bypass or data exposure
- The affected route, endpoint or file paths
- Steps to reproduce, and any proof-of-concept
- The impact, and how an attacker might use it
- Any reference code the app showed

We'll acknowledge your report, keep you updated while we investigate, and credit you in the advisory if you'd
like.

## Scope

In scope: the 6ixstack web app, API, calendar feeds, sign-in links and the code in this repository.

Out of scope: denial-of-service testing, social engineering, physical attacks, and issues in third-party
services we don't control.

## Safe harbour

We won't pursue action against good-faith research that avoids privacy violations, data destruction and
service disruption, and that gives us reasonable time to fix the issue before it is disclosed.
