# L2 - Detailed Requirements

Source: the HTML mocks in `docs/mocks/`. Each requirement traces to one L1 in
`docs/specs/L1.md`. Mock states are cited as `screen/state` (for example
`events/no-results`). "Today" in examples is Monday, November 2, 2026; all times
are Toronto time (ET) unless stated.

Shared definitions used below:

- **Published event** — an event a moderator approved that is not deleted, whether upcoming, past or cancelled.
- **Upcoming window** — the 14 calendar days starting today in ET.
- **GTA event** — an event whose format is in person or hybrid.
- **Streamable event** — an event whose format is streaming or hybrid.
- **Topics** — the fixed set AI, .NET, Azure, Angular, React, AWS, each with a hue that is always shown with its name.
- **Visitor** — an anonymous user; **organizer** — a signed-in user who manages one community's events; **moderator** — a signed-in user with the moderator role.

## L2-001: Upcoming event list grouped by day
**Traces to:** L1-001

The events page (`/`) shall list every published, non-cancelled event in the upcoming window in chronological order, grouped under one heading per day ("Thursday November 5"), with a result line stating the count and "times in ET".

**Acceptance Criteria:**
1. Given 14 published events in the upcoming window, when a visitor opens `/`, then 14 rows appear under day headings in start-time order and the result line reads "14 events · times in ET".
2. Given an event row, when it renders, then it shows the start time, title (linked to the event detail page), organizer, location ("venue, city", "Streaming online", or venue plus "+ stream" for hybrid), each topic with its name, the price ("Free", "$49") and the going count with an accessible label "318 going".
3. Given a streaming event hosted in another time zone, when its row renders, then the source time ("9:00 AM PT") appears under the ET start time.
4. Given an event that is in review, rejected, draft or deleted, when a visitor opens `/`, then that event does not appear.
5. Given a day with no events, when the list renders, then no heading appears for that day.

## L2-002: Format filter with live counts
**Traces to:** L1-001

The events page shall offer a single-select format switch with the options All, In the GTA and Streaming, each showing the number of events that match the current search and topic filters; hybrid events count toward both In the GTA and Streaming.

**Acceptance Criteria:**
1. Given the default data set, when the page loads, then the switch reads All 14, In the GTA 9, Streaming 7, with All pressed (`aria-pressed="true"`).
2. Given a visitor selects In the GTA, when the list updates, then only in-person and hybrid events remain, and the map shows only those events.
3. Given the AI topic is selected, when counts update, then they read All 6, In the GTA 4, Streaming 3 (`events/filtered`).
4. Given counts are unavailable (load error), when the switch renders, then each count shows "–".

## L2-003: Topic filter
**Traces to:** L1-001

The events page shall offer one toggle chip per topic; selecting one or more chips shall show only events tagged with at least one selected topic, and a "Clear filters" action shall reset topics, format and search.

**Acceptance Criteria:**
1. Given no chips are pressed, when a visitor presses AI, then 6 events remain, the result line reads "6 events about AI · times in ET · Clear filters", and the AI chip has `aria-pressed="true"`.
2. Given AI and React are pressed, when the list updates, then events tagged AI or React are shown.
3. Given filters are active, when the visitor activates Clear filters, then all events are shown and an info toast "Filters cleared · Showing all 14 events." with an Undo action appears.
4. Given the Undo action of that toast is activated within its lifetime, when the list updates, then the previous topics, format and search are restored.

## L2-004: Event search
**Traces to:** L1-001

The events page shall provide a search box ("Search talks, groups, or neighbourhoods") that matches, case-insensitively, against event title, organizer name, venue, city and description, combined with the format and topic filters.

**Acceptance Criteria:**
1. Given a visitor searches "signals", when results update, then "Signals all the way down" is listed.
2. Given a visitor searches "markham", when results update, then "GTA AI Builders Hackathon" (ventureLAB, Markham) is listed.
3. Given the search "Kubernetes" with In the GTA selected matches nothing, when results update, then the no-results state shows "No events match those filters", a "Clear filters" primary action and a "Get a feed for Kubernetes" action, the hero stat reads "No matches for “Kubernetes” in the next two weeks.", and the filters stay visible (`events/no-results`).
4. Given a search of more than 100 characters, when submitted, then the query is truncated to 100 characters before it is sent.

## L2-005: Shareable and remembered filters
**Traces to:** L1-001

The events, calendar, communities and speakers pages shall reflect search and filter state in the URL query string, and the events page shall remember the last topic and format selection in browser storage.

**Acceptance Criteria:**
1. Given a visitor selects AI and In the GTA, when the URL updates, then it contains the topic and format parameters, and opening that URL in a new browser shows the same filtered list.
2. Given a visitor returns to `/` without query parameters, when the page loads, then the previously stored topic and format selection is applied.
3. Given browser storage is blocked, when the visitor changes a filter for the first time, then a warning toast "We can't remember your filters" explains that topics reset when the tab closes (`app-toast/warning`), and filtering still works.
4. Given an unknown topic or format value in the URL, when the page loads, then the value is ignored and no error is shown.

## L2-006: Featured event
**Traces to:** L1-001

The events page shall show one featured event beside the hero headline, labelled "Featured this week", with date tile, title, organizer, description, location, livestream availability, day and start time, and a primary action; when no event is featured, it shall show an invitation to submit one.

**Acceptance Criteria:**
1. Given Azure Data & AI Day GTA is featured, when the page loads, then the card shows "Nov 5", the title linked to its detail page, "Living Arts Centre, Mississauga", "Livestream available", "Thu · 9:00 AM" and "Get tickets · $49".
2. Given no featured event exists for the current week, when the page loads, then the card reads "Your event could be here", "Free to list" and a "Submit an event" action (`events/empty`).
3. Given a moderator marks a different published event as featured, when the page next loads, then only that event is featured.
4. Given the featured event is cancelled, when the page loads, then it is no longer featured.

## L2-007: Hero headline and counts
**Traces to:** L1-001

The events page hero shall state the number of GTA events and streamable events in the upcoming window.

**Acceptance Criteria:**

## L2-008: Events page loading, empty and error states
**Traces to:** L1-001

The events page shall render a loading state, an empty state and an error state that keep the hero, filters and map frame in place.

**Acceptance Criteria:**
1. Given events take longer than 300 ms to load, when the page renders, then the featured card, rows, counts and map show skeletons and the result line reads "Loading events…" (`events/loading`).
2. Given no events in the upcoming window, when the page loads, then it shows "No events in the next two weeks" with "Submit an event" and "Browse the calendar" actions, and the map shows "Nothing on the map yet. New events appear here as soon as they're approved." (`events/empty`).
3. Given the events request fails, when the page renders, then an alert "We couldn't load events" offers "Try again" and "Use a calendar feed instead", the filters keep their values, and the map shows "The map fills in once events load." (`events/error`).
4. Given the visitor activates Try again and the request succeeds, when the page updates, then the list renders with the previously selected filters.

## L2-010: Row status badges and long content
**Traces to:** L1-001

Event rows shall show a "Waitlist open" badge for sold-out events and a "Cancelled" badge with cancelled styling for cancelled events, and shall wrap long titles, organizers and venues without horizontal overflow.

**Acceptance Criteria:**
1. Given a sold-out event, when its row renders, then the price reads "Sold out" and a "Waitlist open" badge appears.
2. Given a cancelled event appears in a list (calendar, community, speaker or dashboard), when its row renders, then the "Cancelled" badge appears and the row links to the cancelled detail page.
3. Given a 170-character title, a 75-character organizer, all six topics and a 5-digit going count, when the row renders at 360 px width, then the text wraps and the page has no horizontal scroll (`events/edge`).

## L2-011: Event map plotting
**Traces to:** L1-002

The events page shall show a "Where it's happening" map that plots each GTA event in the current result set as a dot coloured by its first topic at its venue coordinates, marks hybrid events with a dashed ring, and draws each streaming-only event as an arc from its origin city to Toronto.

**Acceptance Criteria:**
1. Given the default data set, when the map renders, then 9 venue dots (2 with dashed rings for the hybrid events) and arcs for the 5 streaming-only events appear, with a subtitle summarising the counts.
2. Given the AI topic filter, when the map updates, then it shows only the AI events in the list.
3. Given a hybrid event, when its dot renders, then it has a dashed ring.
4. Given a venue without coordinates, when the map renders, then the event is omitted from the map and still appears in the list.

## L2-012: Map and list linking
**Traces to:** L1-002

Hovering or focusing an event row shall highlight its dot and show its card on the map; activating a dot shall scroll the list to that event, centred, and move keyboard focus to its row.

**Acceptance Criteria:**
1. Given a pointer hovers the "What's new in the .NET 11 previews" row, when the map updates, then its dot lifts and a card with the title appears (`events/default`).
2. Given a visitor clicks a dot, when the list scrolls, then the matching row is centred in the viewport and has focus.
3. Given the operating system requests reduced motion, when a dot is clicked, then the list jumps to the row without smooth scrolling.

## L2-013: Day focus on the map timeline
**Traces to:** L1-002

A timeline under the map shall show each day of the upcoming window; choosing a day with events shall filter the map to that day, dim the other days in the list and, at viewport widths of 1024 px and above, scroll the list to that day.

**Acceptance Criteria:**
1. Given a visitor picks Thursday, November 5, when the view updates, then the map shows only that day's events, other day groups are dimmed, and the result line ends "showing Thursday, November 5" (`events/day-focus`).
2. Given a day is focused, when the visitor picks it again or activates "Show all dates", then the focus clears and all days are undimmed.
3. Given a day without events, when the timeline renders, then that day is disabled.
4. Given a viewport narrower than 1024 px, when a day is picked, then the list does not scroll.

## L2-014: Timeline playback
**Traces to:** L1-002

A "Play the next two weeks" control shall step the day focus through each day with events every 1.1 s, skipping days without events, and stop on the last such day.

**Acceptance Criteria:**
1. Given the visitor activates Play, when playback runs, then the focus advances every 1.1 s and the result line reads "playing: Tuesday, November 10" while that day is focused (`events/playing`).
2. Given playback is running, when the visitor activates Pause, then playback stops on the current day.
3. Given playback is running, when the visitor picks a day by hand, then playback stops and that day is focused.
4. Given playback reaches the last day with events, when the step completes, then playback stops and the control returns to Play.

---

## L2-015: Map resilience and states
**Traces to:** L1-002

The map shall load independently of the list; a map failure shall not affect the list, filters or featured event.

**Acceptance Criteria:**
1. Given the map fails to load, when the page renders, then the map shows "The map didn't load. The list has every event." with "Try again", and the list shows all events (`events/partial`).
2. Given events are loading, when the map renders, then it keeps its final size and shows "Plotting events…" with `aria-busy="true"`.
3. Given a screen reader user, when the map renders, then its labels are hidden from assistive technology and the list remains the accessible route to every event.

**Traces to:** L1-002

The map shall sit beside the list and stay sticky while the list scrolls at viewport widths of 992 px and above, and shall sit above the list at narrower widths.

**Acceptance Criteria:**

## L2-019: Streaming event detail
**Traces to:** L1-003

A streaming event shall show both the ET time and the time where it is hosted, the streaming platform, a "Join the stream" action that becomes active 15 minutes before the start, a countdown alert before then, and a "Where it streams from" map.

**Acceptance Criteria:**
