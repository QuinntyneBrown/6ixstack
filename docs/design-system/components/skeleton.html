Skeleton

Skeletons hold the shape of content while it loads, so nothing jumps when it arrives.

WCAG 2.2 AAStatus: stablearia-busy

Overview

A skeleton is a grey placeholder in the shape of the content that is about to load: event rows, community cards, a speaker's name and photo. It shows the layout before the data arrives, so nothing jumps when it does.

  • Use skeletons for the first load of a list, grid or detail page.
  • Use a spinner for a small panel or a busy button, and a progress bar for a long task.
  • Don't use skeletons when refreshing content that is already on screen; keep the old content and mark the region busy.

Anatomy

  1. Time block.skeleton--lg (20px), the width of "6:30 PM".
  2. Title and organizer lines70% and 40% wide, lg and md heights.
  3. Meta lines.skeleton--sm (14px) for venue and topic.
  4. AsidePrice and "going" count placeholders.

Variants

Shapes

Title, text lines (the last one 60% wide), circle (avatars, logos) and rect (date tiles, images).

Sizes

Text-line heights follow the type scale they stand in for, replacing the ad-hoc inline heights in the loading mocks.

.skeleton--sm 14px (meta), --md 16px (body), --lg 20px (titles in rows), --xl 24px (page titles).

States

Skeletons have two states: shimmering while loading, and gone. They have no pointer or focus states because they are not interactive.

Responsive behaviour

  • Skeletons are built from the same layout classes as the real content (.event-row, .card-grid, .dir-card), so they reflow exactly like it: one column of cards on phones, a grid from 640px.
  • Widths are percentages of their column, so lines shorten on small screens instead of overflowing; fixed rem widths are only for things with a fixed real size (time "6:30 PM", logos).
  • Show as many skeleton rows as fit the first screen: three on phones, five on desktop. Never more than one screen.

Theming

The shimmer is a gradient between --color-bg-subtle and --color-bg-subtle-hover. The dark theme raises both, so skeletons read as slightly lighter than the surface, which keeps them visible without looking like real content.

Accessibility

Role and pattern

Skeleton blocks are aria-hidden="true". The region they fill gets aria-busy="true" while loading, and a polite status line says what is happening. pages/events/loading uses the result line for this: <p class="result-line" role="status">Loading events…</p>, which then becomes "14 events" when the list arrives.

Keyboard

KeyAction
TabSkips skeletons entirely; filters and search above the list stay usable while it loads.

Focus

Loading never moves focus. If focus was on the list (after "Clear filters"), it stays on the region container until content arrives.

Labelling

Only the status line is announced. Do not label individual skeleton shapes.

Contrast

Skeleton on card (decorative, not text)
Status line

Skeletons are exempt from 1.4.11 because they convey no information; the status line carries it.

Motion

The shimmer sweeps once per --duration-shimmer (1.4 s). Under prefers-reduced-motion the token is zeroed and the component CSS stops the animation, leaving a static grey block.

Touch

Not interactive.

Content

  • No text inside skeletons. The status line says "Loading events…", "Loading communities…".
  • When loading takes longer than about 10 seconds, replace the skeleton with an error alert offering Try again.
