Pagination

Pagination moves through long result sets: load more for browsing lists, numbered pages where position matters.

WCAG 2.2 AAStatus: stable<nav> + <button>

Overview

Pagination moves through a long result set in pages. 6ixstack's lists (events, communities, speakers) are browsed top to bottom, so the mocks use load more: a count of what is shown and a button that appends the next 20. Numbered pagination is the core-set variant for places where position matters and people return to a page, such as the review queue or an organizer's past events.

  • Use load more on public browse lists; it keeps the map and filters in place and the scroll position stable.
  • Use numbered pages for work queues and tables where people need "page 4" to mean the same rows tomorrow.
  • Never use infinite scroll: the footer (code of conduct, calendar feeds, organizer sign in) must stay reachable.

Anatomy

  1. Previous / next32px icon links named "Previous page" / "Next page"; aria-disabled at the ends.
  2. Page links and current page32px min-width; current has aria-current="page", an accent-subtle fill and an accent edge. Gaps are "…".
  3. Result countCaption text in a role="status" region: "Showing 10 of 86 communities".
  4. Load more buttonSecondary button, "Show 20 more"; busy while the next page loads.

Showing 10 of 86 communities

  • Busy: the load-more button sets aria-busy="true"; when rows arrive, the count updates in its live region and focus moves to the first new row.
  • Complete: when everything is shown the button is removed and the count reads "Showing all 86 communities".

Responsive

  • Below 640px numbered pagination shows previous, current and next only, plus first and last with gaps; never more than seven slots.
  • The load-more block is centred under the list at every width, with --space-8 above it.
  • In the Events page's list-plus-map layout, load more belongs to the list column so the map stays put.

Theming

Page links read --color-fg-muted, --color-bg-subtle (hover) and, when current, --color-accent-subtle fill, --color-fg-accent label and --color-accent edge. The load-more button uses the secondary button tokens.

Accessibility

Role and pattern

<nav aria-label="Pagination"> around a list of links; the current page has aria-current="page". Load more is a native <button> plus a polite role="status" count; there is no APG widget pattern for either.

Keyboard

KeyAction
TabMoves through previous, page links, next (disabled ends are skipped via aria-disabled plus tabindex="-1").
EnterFollows a page link.
Enter / SpaceOn load more, fetches the next rows and moves focus to the first new one.

Focus

Shared focus ring. After load more, focus goes to the first appended row so keyboard users do not have to Tab through everything already read.

Labelling

Page links are named "Page 4"; arrows "Previous page" / "Next page". The count is a live region so "Showing 30 of 86 communities" is announced after loading.

Contrast

Page number on surface
Current page label
Current page edge
Count caption on page

Motion

No animation; the button's busy spinner keeps turning under reduced motion because it reports status.

Touch

Page links are 32px squares with 4px gaps (above 24px minimum); on phones prefer load more, whose button is 40px tall.

Content

  • Count format: "Showing 10 of 86 communities"; add the date bound when filtered by time: "Showing 14 of 61 events through December 31".
  • Button: "Show 20 more", naming the batch size, never "Load more…" or "See all".
  • Use the noun of the list ("communities", "speakers", "events").
