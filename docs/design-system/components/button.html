Button

Buttons let people act: submit an event, subscribe to a feed, add a meetup to their calendar. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it submits a form, opens a dialog such as Add to calendar, copies a feed link or starts sign-in. Use a link when it only takes the person to another page, such as an event detail. Use a menu when one trigger offers several actions, and a button group for a set of mutually exclusive views.

  • Primary is the one action the view exists for: Submit for review, Email me a sign-in link, Subscribe. Never two per view.
  • Secondary (the default look) is every other action that is still an action: Cancel, Add to calendar, Load more events.
  • Ghost sits in dense places: the site header, event rows, toast and dialog close buttons.
  • Link looks like a link but behaves like a button; for low-emphasis actions inside sentences and cards.
  • Danger is for destructive actions (Delete account, Cancel event, Reject submission) and appears only inside a confirmation dialog.

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, padding --space-3/4/6.

Variants

Emphasis from highest to lowest; danger is reserved for destructive confirmations.

Sizes

Heights --control-height-sm/md/lg; padding --space-3/4/6; font --font-size-sm/md/lg. Small lives in event rows, toolbars and the calendar view switch; large on sign-in and the hero.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button>
<button class="btn btn--primary" type="button">Medium · 40px</button>
<button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks. Use it on the button that was pressed (Submit for review), not the whole form.
  • Disabled uses the native attribute; it is not focusable and is 50% opaque. Prefer an enabled button that explains the problem on press, as the submit form does with its error summary.
  • Pressed (aria-pressed) and expanded (aria-expanded) belong to toggles and menu triggers; see button group and menu.

Responsive behaviour

  • Below --layout-breakpoint-md (768px) the primary action of a form or page header becomes full width (.btn--block); on event detail it moves into the sticky bottom CTA.
  • The header's Submit an event button drops its label below 768px and keeps the icon plus aria-label.
  • Dialog footers keep buttons on one row and wrap when narrower than their content; the primary or danger button stays last.
  • Labels never truncate; a label that wraps at 360px is too long.

Theming

The button reads semantic tokens through five component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active) that each variant overrides. Themes change the semantic tokens; a re-skin overrides component tokens.

/* An orange primary for a campaign page, without touching .btn */
.campaign .btn--primary { --btn-bg: var(--color-brand); --btn-border: var(--color-brand); --btn-fg: var(--color-fg-on-brand); }

6ixstack's primary is ink, not orange: in light it is near-black with white text; in dark it flips to warm off-white (#f3f2ee) with ink text, staying above 15:1. Orange is kept for the focus ring and brand text.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" in a form. Something that navigates is an <a href> with button classes (Cancel back to events). No ARIA role is needed; see the APG Button pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button; inside a dialog it closes the dialog.

Focus

The shared ring (2px --color-focus-ring, orange, 2px offset) appears on :focus-visible only. The offset gap shows the surface, so the ring stays above 3:1 against both an ink button and the page.

Labelling

The visible label is the name. Icon-only buttons set aria-label with the object: “Share event”, “Close”, “Dismiss notification”. Loading buttons keep their name and add aria-busy; “Sending your message…” is announced in the form's live region.

Motion

Background and border transition over --duration-fast (120ms); active translates 1px. Reduced motion zeroes the durations in the tokens. The loading spinner keeps turning; it is status, not decoration.

Touch

Medium (40px) and large (48px) meet the 24px minimum; mobile primary actions use large or block. Small (32px) buttons sit in rows with 8px between them.

Content

  • Verb phrases in sentence case: “Submit for review”, “Add to calendar”, “Copy link”, “Load more events”. Never “OK”, “Submit”, “Click here”.
  • Name the object when context does not: “Delete account”, “Cancel event”, “Reject submission”, not “Confirm”.
  • The safe choice says what is kept: “Keep account”, “Keep event”.
  • Three words or fewer where possible.
  • Loading keeps the label; progress text goes in a live region next to the button.
