Progress bar

Progress bars show how far a longer task has got, and whether it finished.

WCAG 2.2 AAStatus: stablerole=progressbar

Overview

A progress bar shows how far a task that takes more than a couple of seconds has got: importing a community's events from Meetup, building a calendar feed, uploading a speaker photo. It answers "is it still working, and how long?"

  • Determinate when the total is known (12 of 24 events imported).
  • Indeterminate when it is not, but the task will take more than about 2 seconds.
  • For a short action on a button (Save, Approve), use the button's busy state with a spinner. For content loading into a region, use a skeleton.

Anatomy

  1. Label--text-label; names the task; also the accessible name.
  2. Value (optional)Counts beat percentages: "12 of 24".
  3. Track8px tall, --color-bg-subtle-hover, fully rounded.
  4. Bar--color-accent; width from --value.

When the task finishes, the bar turns success, the label changes ("Import complete"), and the completion is announced. It does not disappear on its own; the next step (a link to the imported events) replaces it.

Responsive behaviour

  • The track fills its container at every width.
  • Below 360px the value text moves under the label when both do not fit on one line.

Theming

Track --color-bg-subtle-hover, bar --color-accent (ink on light, near-white on dark), success --color-success-solid, danger --color-danger-solid. Override the bar per context with .progress__bar { background: … } using a semantic token.

Accessibility

Role and pattern

role="progressbar" with aria-label (or aria-labelledby pointing at the visible label), aria-valuemin, aria-valuemax, aria-valuenow and a human aria-valuetext ("12 of 24 events imported"). Indeterminate bars omit aria-valuenow and set aria-busy="true" on the region being updated.

Keyboard

KeyAction
—Not focusable. Any Cancel action next to it is a normal button.

Focus

Progress never takes focus. On completion, focus stays where it is; the result is announced via the page's polite live region ("All 24 events imported").

Labelling

Announce start and finish, not every step; updating a live region on every percent floods screen readers. Every 25% is the most often a value should be announced.

Contrast

Bar on track
Success bar on track
Danger bar on track
Value text

Motion

Width changes ease over --duration-slow. The indeterminate bar sweeps over --duration-shimmer. With reduced motion the sweep stops and the bar fills the track at reduced opacity, so it still reads as "working".

Touch

Not interactive.

Content

  • Label the task with a verb in -ing: "Importing from Meetup", "Creating your feed".
  • Prefer counts to percentages; give an estimate on indeterminate bars ("Usually under 10 seconds").
  • On failure, say where it stopped and what is kept: "Stopped at 17 of 24. The 17 imported events are saved."
