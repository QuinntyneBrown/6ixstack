Site header

The site header carries the wordmark, the four primary destinations and the one action every visitor can take: submit an event.

Overview

The site header is the one piece of chrome on every public 6ixstack page: the wordmark, the four primary destinations (Events, Calendar, Communities, Speakers) and the single most important action, Submit event. It sticks to the top of the viewport over a translucent canvas so the event list scrolls underneath it.

  • Use it on every page that a visitor can browse: lists, details, directory pages, forms, status pages (404, 500, offline) and sign-in.
  • Do not add page-specific actions to it. Filters, view switches and "Add to calendar" live in the page body (see button group and button).
  • Organizer screens (dashboard, edit event, review queue) keep the same header; their own sections use sidebar navigation inside the page.

Anatomy

  1. BrandInk tile with "6" plus the "6ixstack" wordmark; one link home, named "6ixstack home".
  2. Primary navigationnav aria-label="Primary" with four .nav-links; current page is semibold ink, not a filled pill.
  3. ActionsPrimary "Submit event" button; the label collapses to the plus icon below 768px, and a ghost menu button appears.
  4. Bar64px tall, --color-bg-header with an 8px backdrop blur, hairline --color-border-default bottom edge, content capped at --layout-container-max.

Variants

There is one header. It has two layouts, chosen by viewport width, and the only content that changes between pages is which link is current.

  • Current page uses aria-current="page"; in the header it is shown by weight and ink colour only, so the bar stays quiet. Inside the mobile menu and settings navigation the current link also gets a --color-bg-subtle fill.
  • Expanded: when the menu is implemented as a button rather than a link to the menu screen, it carries aria-expanded and aria-controls pointing at the menu dialog.
  • Scrolled: the bar does not change on scroll; the translucent background and blur keep it legible over any row.

Responsive

  • Below 768px (--layout-breakpoint-md): the primary nav is hidden, "Submit event" becomes a 40px icon-only primary button (its aria-label keeps the name), and the ghost menu button opens dialogs/mobile-nav, a full-height sheet listing the same four destinations in the same order.
  • 768px and up: nav is shown centred between brand and actions; the menu button is removed from the layout (not just hidden visually), so it is not in the tab order.
  • 1280px and up: the inner row stops growing at --layout-container-max and centres, aligned with the page content below it.
  • Horizontal padding is --layout-margin (16 / 32 / 48px), so the brand lines up with the page's first column at every breakpoint.
  • The page sets scroll-padding-top to the header height so focused elements and in-page targets are never hidden under it (WCAG 2.4.11).

Theming

The header reads --color-bg-header (canvas at 90% opacity in light, 88% in dark), --color-border-default, --color-fg-muted for links and --color-fg-default for the current link, and the primary button tokens. The brand tile uses --color-accent and --color-fg-on-accent, so in dark theme it flips to a light tile with an ink "6".

/* A partner or event-week theme only touches semantic tokens */
[data-theme="partner"] { --color-bg-header: var(--color-bg-surface); }

Do not give the header its own colours; when the canvas changes, the header follows.

Accessibility

Role and pattern

A <header> landmark (banner) containing a <nav aria-label="Primary"> of plain links; no ARIA menu roles. The mobile menu follows the APG Dialog (Modal) pattern: see dialog and drawer.

Keyboard

KeyAction
TabSkip link first, then brand, the four nav links, Submit event, and (below 768px) the menu button.
EnterFollows the focused link; on the menu button, opens the mobile menu and moves focus to its first link.
EscCloses the mobile menu and returns focus to the menu button.
Arrow keysNo effect: these are links, not a menubar, so they keep normal Tab behaviour.

Focus

The shared ring (2px --color-focus-ring, 2px offset) on every link and button. The header is sticky, so scroll-padding-top: 4rem keeps focus visible below it.

Labelling

The brand link is named "6ixstack home" and its visual text is aria-hidden so it is not read twice. The icon-only Submit event keeps the accessible name "Submit event" via aria-label; the menu button is "Open menu". The landmark label "Primary" distinguishes it from the "Footer" and "Settings sections" navs.

Motion

Nav links transition background and colour over --duration-fast. The mobile menu sheet slides in over --duration-slow; with reduced motion the tokens zero both and the sheet appears in place.

Touch

Nav links are 44px tall (--target-comfortable); the menu and icon-only Submit buttons are 40px squares with 8px between them, above the 24px minimum. The mobile menu's links grow to 48px.

Content

  • Nav labels are single nouns naming the destination: Events, Calendar, Communities, Speakers. Keep this order everywhere it appears (header, mobile menu, footer of the about page).
  • The one header action is a verb phrase: Submit event. Never "Add", "Post" or "+ New".
  • Do not add counts or badges to header links; "12 new events" belongs in the page.
  • The wordmark is always "6ix" bold plus "stack" muted; never spell it "Sixstack" in the UI.
