Card

Cards group one thing (a community, a speaker, a submission, a form section) on a raised surface so it can be scanned, compared and acted on.

WCAG 2.2 AAStatus: stableNative <article>

Overview

Use a card when a page shows a collection of comparable things (communities, speakers, submissions) or when a form needs grouped sections. Use an event row for event listings, where time is the first thing people scan, and a list when items have no supporting text. The one ink card on the home page is the feature card.

  • Directory card (.dir-card) is a link card: the whole card opens a community or speaker.
  • Review card (.review-card) holds a pending submission and its moderator actions; the card itself is not a target.
  • Form card (.form-card) wraps a long form, such as Submit event, in one surface.
  • Basic card (.card) with __header, __title and __footer for settings panels and dashboard widgets; .card--flush for edge-to-edge media and tables.

Anatomy

  1. Container--color-bg-surface, 1px --color-border-default, --radius-lg, 20–24px padding.
  2. Media / logo tile (optional)44px tile with initials; decorative, aria-hidden.
  3. Title linkThe one real control. Its ::after stretches over the card so the whole card is clickable.
  4. Supporting text--text-body-sm in --color-fg-muted.
  5. FooterSeparated by a hairline; holds metadata and topic tags, pinned to the bottom with margin-top: auto.

Variants

All variants share the surface, border and radius; they differ in what is interactive.

Sizes

Cards have one size; width comes from the grid they sit in and padding is fixed at --space-5 (directory, review) or --space-6 (basic, form).

States

Only link cards have pointer states. Pointer and focus states are forced here with data-state; in the product they come from :hover, :focus-visible on the title link (via :has()) and :active.

  • Hover raises the border to --color-border-strong and the shadow to --shadow-2.
  • Focus is drawn on the card, not the title, because the stretched link covers the card.
  • Loading uses the skeleton card shape (logo circle, two text lines); see pages/communities/loading.

Responsive behaviour

  • .card-grid is repeat(auto-fill, minmax(min(100%, 17rem), 1fr)): one column at 360px, two from about 600px, three or four at 1280px. No media queries.
  • Review cards stack their actions under the content below --layout-breakpoint-md (768px) and move them to a right-hand column above it.
  • Form cards keep 24px padding at every width; the fields inside follow the form layout rules (one column below 768px).
  • Card titles wrap (overflow-wrap: anywhere) rather than truncate, so long community names stay readable at 320px.

Theming

Cards read --color-bg-surface, --color-border-default, --color-border-strong (hover) and --shadow-1/2. In the dark theme the surface (#16181d) is one step lighter than the canvas and shadows deepen, so cards still read as raised.

/* A sunken variant for a settings sidebar, without touching .card */
.settings-panel.card { background: var(--color-bg-surface-sunken); box-shadow: none; }

Accessibility

Role and pattern

An <article> (or <li> inside a <ul class="card-grid">) with a heading. A clickable card has exactly one real link, the title; its ::after pseudo-element stretches over the card. The card is never a <div onclick> and never wraps other controls inside a link.

Keyboard

KeyAction
TabMoves to the title link (one stop per card), then to any secondary controls inside the card.
EnterFollows the title link.
SpaceScrolls the page, as for any link.

Focus

The ring is drawn around the whole card with :has(a:focus-visible), 2px --color-focus-ring with a 2px offset, so it follows the card radius.

Labelling

The heading text is the link's accessible name; keep supporting text out of the link so it is not read twice. Repeated action buttons carry a visually hidden object ("Reject Rust in production at scale"). Decorative logo tiles are aria-hidden.

Contrast

Body text on card
Supporting text on card
Hover border on canvas
Selected outline on canvas
Topic dot on card

Motion

Border colour and shadow transition over --duration-fast; interactive basic cards also lift 1px. Reduced motion zeroes the duration, so the change is instant.

Touch

The whole card is the target (well above 44px). Hover is an enhancement only; on touch the card looks the same and still works on tap.

Content

  • Title: the thing's real name ("Toronto .NET User Group"), never "Learn more".
  • Subtitle: place and size, separated by a middle dot ("Mississauga · 2,140 members").
  • Description: one sentence, about 90 characters, saying what makes this one different.
  • Footer: the next event first, then up to three topic tags.

Drift fixed during extraction:

  • pages/review-queue/default sets data-state="hover" on a review card, which has no hover style because it is not a target. Resolution: review cards have no pointer states; the attribute should be removed from the mock.
  • The global [data-state="focus"] rule set --radius-sm on any element, squaring off forced-focus cards. Resolution: cards keep --radius-lg when focus is forced.
  • Review-card content wrappers use style="min-width: 0;" inline; kept as-is (layout, no colour) and noted for the Angular component.
