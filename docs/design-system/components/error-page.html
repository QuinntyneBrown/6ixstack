Error page

Error pages replace a page that can’t be shown, say why in plain words, and offer a way out.

WCAG 2.2 AAStatus: stableFull page

Overview

An error page replaces the page content when the whole page cannot be shown: the address does not exist (404), the person may not see it (403), the server failed (500), or the device is offline. The site header and footer stay, so people can navigate away.

  • Use an error page only when there is nothing useful left to show.
  • When part of a page failed (the events list), use an alert in that region and keep the rest.
  • When a region is permitted but empty or blocked inside an otherwise working page, use an empty state (pages/review-queue/forbidden does this rather than a 403 page).

Anatomy

  1. Status codeHero mono numerals with the brand full stop; aria-hidden, decoration only.
  2. TitleThe page's h1: what happened, in words.
  3. ExplanationWhy, and what still works; --color-fg-muted.
  4. Recovery actionsOne primary, up to two more.

Responsive behaviour

  • Centred at every width, inside the normal page shell (site header and footer stay).
  • The status code uses --font-size-hero (48–72px, fluid); the title drops to --text-h2 at every size.
  • Below 360px the actions stack, primary first.
  • As a full page it keeps a minimum height of the viewport minus the header and footer, so the footer does not ride up; embedded (.status-page--inline) it has none.

Theming

The code uses --color-fg-default with the full stop in --color-brand, the 6ixstack mark. The orange stop is decorative (the code is hidden from assistive technology), so it is exempt from contrast minimums in the light theme. Title and text use the default and muted foregrounds.

Accessibility

Role and pattern

A normal page: unique <title> ("Page not found — 6ixstack"), one h1 (the sentence title), landmarks from the shell. The HTTP status is returned by the server; the visible code is aria-hidden="true" so it is not read as "four hundred four".

Keyboard

KeyAction
TabSkip link, header navigation, then the recovery actions in order.
EnterActivates the action.

Focus

On a client-side route change into an error page, focus moves to the h1 (with tabindex="-1") so the change is announced.

Labelling

The title says what happened in plain words; the reference id on the 500 page is selectable text, not an image.

Content

  • Title in words, not codes: "We can’t find that page", "You can’t edit this event", "Something broke on our side", "You’re offline".
  • Say whose side the problem is on: "It’s not you."
  • 403: name the owner and the account they are signed in with, and who can grant access.
  • 500: give a reference id and an email address.
  • Offline: say what is still available.
