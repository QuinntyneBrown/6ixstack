Feature card

The ink “Featured this week” card puts one hand-picked event in front of everyone who opens 6ixstack.

Overview

The feature card sits in the home-page hero beside the headline. It is the only ink (near-black) surface in the light theme, so it draws the eye before the event list does. Use it for exactly one event the editors chose this week. For everything else use an event row; for communities and speakers a card.

Its button is the one place the .btn--on-feature variant appears: an inverted button (light fill, ink label) that stays legible on the ink surface.

Anatomy

  1. Label“Featured this week”, --text-body-sm in --color-fg-on-feature-muted.
  2. Date tileMonth and day on --color-bg-feature-tile; decorative because the time line repeats the date.
  3. Title link and organizerThe title is the link to the event; the organizer sits under it.
  4. DescriptionOne or two sentences, relaxed line height.
  5. MetaVenue, plus “Livestream available” with the brand-orange glyph when the event streams.
  6. FooterDay and start time in mono, and the on-feature button with the price.

Variants

One layout. The content varies: in-person only (no stream line), streaming only (venue replaced by “Online”), and free (the button says “RSVP · Free”).

  • A sold-out event keeps the card but the button reads “Sold out” and is aria-disabled; better still, feature a different event.
  • In the dark theme the card becomes a raised surface (#1e2026) with a visible border instead of ink-on-ink.

Responsive behaviour

  • Below --layout-breakpoint-lg (1024px) the hero stacks: headline first, feature card under it, full width.
  • The footer wraps: on a 360px screen the time sits on its own line and the button goes full row width.
  • The description is the first thing to cut if a future compact variant is needed; title, time and button never are.

Theming

The card reads a dedicated group of semantic tokens so it can stay ink in light and become a raised surface in dark: --color-bg-feature, --color-border-feature, --color-fg-on-feature, --color-fg-on-feature-muted and --color-bg-feature-tile. The button maps them into its component tokens:

.btn--on-feature {
  --btn-bg: var(--color-fg-on-feature);
  --btn-fg: var(--color-bg-feature);
  --btn-border: var(--color-fg-on-feature);
  --btn-bg-hover: var(--color-bg-canvas);
}

The feature tile was translucent white over ink in the mocks; it is now the opaque --palette-ink-tile so its contrast can be checked.

Accessibility

Role and pattern

A <section aria-labelledby> landmark named by the event title (the mock) or aria-label="Featured this week". The title is an <a>; the button is also an <a> because it navigates to the event page.

Keyboard

KeyAction
TabTitle link, then the ticket button.
EnterFollows the focused link.

Focus

Both links show the shared 2px ring, recoloured to --color-fg-on-feature inside the card; it measures above 3:1 against the ink surface.

Labelling

The button label carries the price (“Get tickets · $49”) so it makes sense out of context. The date tile is aria-hidden; the time line and the event page give the date in text.

Motion

Only the button's background transitions (--duration-fast). Nothing auto-rotates: there is one featured event, not a carousel.

Touch

The button is 40px tall with the full card width available on phones.

Content

  • Label is always “Featured this week”.
  • Title and organizer exactly as on the event page.
  • Description: what people will learn, under 140 characters.
  • Time line: short day and time in Toronto time (“Thu · 9:00 AM”).
  • Button: verb plus price (“Get tickets · $49”, “RSVP · Free”, “Watch live”).
