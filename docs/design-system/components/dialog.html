Dialog

A dialog interrupts the page to confirm a consequential action or collect a short piece of input, then returns people exactly where they were.

WCAG 2.2 AAStatus: stableAPG Dialog (Modal)Bottom sheet below 640px

Overview

Use a dialog when the person must decide before continuing: cancelling an event, deleting an account, rejecting a submission, reporting an event, subscribing to a feed, signing out. Use a popover for small, non-blocking extras, a drawer for long side tasks, and a full page for anything with more than one screen of fields (Submit event is a page, not a dialog).

  • Default asks a question with two buttons (Sign out).
  • Destructive adds the danger icon and a danger confirm button (Cancel event, Delete account).
  • Form collects a few fields (Report event, Subscribe to a feed, Reject submission) and validates in place.
  • Sheet is the same dialog anchored to the bottom edge on phones; the mobile menu is the only dialog that exists only as a sheet.

Anatomy

  1. Backdrop--color-bg-backdrop scrim; the page behind is inert.
  2. Danger icon (destructive only)40px circle, --color-danger-bg with --color-danger-icon.
  3. Title and descriptionH3 title names the thing; the description says what happens next. Both are wired with aria-labelledby / aria-describedby.
  4. Close buttonGhost icon button, aria-label="Close"; disabled while busy.
  5. BodyFields, alerts, choices; 16px vertical, 24px horizontal padding.
  6. FooterSafe action first, confirm last; sticky at the bottom with a top hairline.

  • Invalid: the field gets aria-invalid="true" and its error joins aria-describedby; focus moves to the first invalid field.
  • Busy: the confirm button sets aria-busy and changes to the present participle (“Cancelling…”); the fieldset, safe action and close button are disabled and Escape does nothing until the request returns.
  • Failed: a danger alert at the top of the body (role="alert") says nothing was lost; the confirm button becomes “Try again”.
  • Confirm (Delete account): the destructive button is enabled only after the person types their email, which guards against a mis-tap.

Responsive behaviour

  • Below --layout-breakpoint-sm (640px) the panel is a bottom sheet: full width, top corners --radius-xl, slides up. From 640px it is centred with --radius-lg and scales in.
  • The footer is sticky, so the confirm button stays reachable when the keyboard is open on a phone.
  • Footer buttons stay on one row and wrap when they do not fit; in the mobile menu the single action is full width and large (48px).
  • Max height is 100dvh minus 48px so mobile browser chrome never hides the footer.

Theming

The panel reads --color-bg-surface-raised, --shadow-4 and --color-bg-backdrop. In the dark theme the raised surface (#1e2026) is two steps above the canvas and the backdrop darkens to 65% black, so the panel separates from the page without relying on shadow alone. Re-theme by overriding those three semantic tokens on a wrapper; never colour a panel directly.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog" + aria-modal="true", labelled by the title and described by the description. In Angular it is a CDK Dialog, which traps focus, sets the rest of the page inert and restores focus. Destructive confirmations use the same pattern, not role="alertdialog", because they always contain more than a message.

Keyboard

KeyAction
Tab / Shift+TabCycles through the dialog's controls only (focus is trapped).
EscCloses the dialog as the safe action; ignored while busy.
EnterActivates the focused button; in a single-field form it submits.
SpaceToggles checkboxes and activates buttons.

Focus

On open, focus goes to the first field, or to the safe action in a destructive dialog (“Keep event” has autofocus). On close, focus returns to the control that opened it (the menu button, the row's Cancel button).

Labelling

The title is the accessible name and should name the object (“Cancel “Azure Data & AI Day GTA”?”). The close button is “Close”. The danger icon is decorative; the word “can’t be undone” carries the warning.

Text on raised panel

Motion

The backdrop fades in over --duration-base; the panel slides up (sheet) or scales in from 96% (centred) over --duration-slow with --ease-enter. Reduced motion zeroes both: the dialog simply appears.

Touch

Close button and footer buttons are 40px; the mobile menu's action is 48px and its links 48px tall. Tapping the backdrop closes non-destructive dialogs only.

Content

  • Title: a question that names the object (“Delete your organizer account?”), or a task for form dialogs (“Report a problem”).
  • Description: the consequence in one or two sentences, ending with “This can’t be undone.” when that is true.
  • Buttons: the confirm verb repeats the title's verb (“Cancel event”, “Delete account”); the safe action says what is kept (“Keep event”, “Keep account”), never “No”.
  • Busy label: present participle with an ellipsis (“Deleting…”).
  • Failure: what didn't happen and that nothing was lost (“Your report didn't send … Nothing you wrote was lost.”).
