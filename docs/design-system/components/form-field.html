Form field

The wrapper every input lives in: label, control, help text and error, stacked with fixed spacing so every form reads the same.

Overview

Every text field, textarea and select sits in a .field. Checkbox and radio groups use a <fieldset> with the same help and error parts. The field owns spacing and the wiring between parts (for, id, aria-describedby).

Anatomy

  1. Label--text-label; “(optional)” in subtle text when it is.
  2. ControlAny input.
  3. Help--text-body-sm, muted.
  4. ErrorDanger text with a warning glyph; added after help.

Parts are --space-1 (4px) apart. Fields in a grid are --space-5 (20px) apart.

Responsive behaviour

  • Label above the control at every width; never beside it.
  • Help and error wrap within the field width.

Theming

Reads --color-fg-default (label), --color-fg-subtle (optional), --color-fg-muted (help) and --color-danger-fg (error).

Accessibility

Role and pattern

A <label for> tied to the control id; help and error ids in the control's aria-describedby (help first, then error); aria-invalid="true" on the control.

Keyboard

KeyAction
TabMoves to the control; the label, help and error are read with it.

Focus

Belongs to the control.

Labelling

The error replaces nothing: help stays so the person still knows the rule. The warning glyph is generated content and not read twice.

Content

  • Labels: nouns, sentence case, no colon.
  • Help: one sentence, what good looks like.
  • Errors: what to do, in the same words as the label (“Enter a title for the event.”).
  • Mark optional fields, not required ones.
