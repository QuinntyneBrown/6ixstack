Drawer

A drawer slides a panel in from the edge for a side task, such as filtering events, that should not replace the page.

WCAG 2.2 AAStatus: stableAPG Dialog (Modal)Not yet used in the mocks

Overview

A drawer is a modal dialog shaped as an edge panel. Use it for tasks that need more height than a dialog but should keep the page in view: filtering the event list on a tablet, reviewing a submission's history. On phones, 6ixstack uses a bottom-sheet dialog instead (the mobile menu), so the drawer is a tablet and desktop pattern.

The mocks do not use .drawer yet; the class ships in the kit so the next side task does not invent its own panel. Do not use a drawer for primary navigation: on 6ixstack navigation lives in the site header and the mobile menu sheet.

Anatomy

  1. BackdropSame scrim as dialogs.
  2. HeaderH4 title and close button, hairline below.
  3. BodyScrolls independently; 24px padding.
  4. FooterSecondary then primary action, right-aligned.

Variants

Right (default) for tasks about the current page; left only when the drawer mirrors a left-hand control. Footer optional for read-only drawers.

Close button, fields and the safe action are disabled while busy, as in dialogs. Pointer states belong to the controls inside.

Responsive behaviour

  • From --layout-breakpoint-sm (640px) the drawer is a 28rem panel against its edge.
  • Below 640px it is full width (min(100%, 28rem)); prefer a bottom-sheet dialog on phones so the thumb reaches the actions.
  • Header and footer stay fixed; only the body scrolls.

Theming

Reads --color-bg-surface-raised, --shadow-4, --color-border-default and --color-bg-backdrop, identical to dialogs, so both overlays always match in either theme.

Accessibility

Role and pattern

APG Dialog (Modal) with role="dialog", aria-modal="true" and aria-labelledby pointing at the drawer title. The trigger has aria-expanded and aria-controls.

Keyboard

KeyAction
Tab / Shift+TabCycles within the drawer.
EscCloses and returns focus to the trigger.
SpaceToggles a topic checkbox.

Focus

Focus moves to the first control in the body on open (not the close button), and back to the trigger (“Filters”) on close.

Labelling

The title names the task (“Filter events”); the primary button states the outcome with a count (“Show 9 events”), updated live.

Contrast

Text on drawer
Metadata on drawer
Checkbox border

Motion

Slides in from its edge over --duration-slow (slide-in-right / slide-in-left); reduced motion makes it appear in place.

Touch

Checkbox rows are at least 24px tall with 8px between them; footer buttons 40px.

Content

  • Title: the task as a verb phrase (“Filter events”).
  • Primary action: the result (“Show 9 events”), not “Apply”.
  • Secondary: “Clear all” resets without closing.
