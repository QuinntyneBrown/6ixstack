Foundation

Color

Warm neutrals, an ink accent, one orange brand dot and a hue per topic, with every pairing checked for WCAG 2.2 AA in light and dark.

Overview

6ixstack's palette is quiet on purpose: warm greys and ink carry the interface so that the six topic hues and a single orange brand dot can do the signalling. Colour is defined in three tiers: primitives (--palette-*, raw values), semantic roles (--color-*, what components read) and component tokens in components.css. Themes only override the semantic tier.

  • Accent is ink. Primary actions are near-black on light and near-white on dark; orange is never a button fill.
  • Orange is the brand mark and the focus ring. Orange text always uses --color-fg-brand (orange-700 / orange-300) to reach 4.5:1.
  • Topic colour is never the only signal: every dot sits beside its topic name.
  • Status is colour + icon + text: “Published”, “In review”, “Cancelled” each carry a word, not just a tint.

Primitive ramps

Warm grey

Neutrals with a faint warm cast; canvas is gray-50, ink is gray-950.

Ink tiles

Opaque stand-ins for white at 10% and 16% over ink, used on the always-dark feature card and event map.

Orange (brand)

The full stop in “6ix.”: brand dot, livestream glyph, focus ring, link hover.

Blue (info)

Info alerts and banners only; never a brand colour.

Green (success)

Success alerts, “Published” status, approval toasts.

Amber (warning)

Warnings, “In review” and “Needs changes” statuses.

Red (danger)

Errors, destructive buttons, “Cancelled” and “Rejected” statuses.

Topic hues

One hue per topic: AI, .NET, Azure, Angular, React, AWS. The -bright set is tuned for the ink event map and the dark theme. A topic colour never stands alone; it is always a dot beside the topic name.

Pure white and black

--palette-white is the surface in light theme and the text on ink. --palette-black exists for shadow and overlay maths; no surface or text uses it.

Semantic roles

Components and pages use these, never primitives. Swatches show the current theme; switch theme with the toggle or t.

Usage

  • Pick a role, not a hue: --color-fg-muted, not --palette-gray-600.
  • Use --color-border-strong for anything a person must find to operate (inputs, checkboxes, switch tracks); --color-border-default for dividers and card edges.
  • Use --color-accent-subtle for selected rows and the current segment; text on it stays --color-fg-default.
  • Use status colours only for status: info for neutral notices, success for completed actions, warning for things that need attention soon, danger for errors and destructive actions.
  • Use topic colours only for topic dots, rings and map marks, always next to the topic name.
  • The event map and the featured card keep their own --color-map-* and --color-*-feature roles; do not reuse them elsewhere.
  • To add a brand theme, add a [data-theme="<name>"] block that overrides --color-* only, then add its pairs to contrast-pairs.json and run check_contrast.py. See Theming.

Accessibility

  • All text pairs above pass WCAG 2.2 AA (1.4.3) in both themes; check_contrast.py enforces them.
  • Control edges, focus ring and meaningful icons pass 3:1 (1.4.11, 2.4.11).
  • --color-brand on canvas is 2.9:1, so the bright orange is used only for decoration beside text (the wordmark dot, the livestream glyph next to “Livestream”).
  • prefers-contrast: more promotes default borders to strong and muted text to default; forced-colors hands borders and the focus ring to system colours.
