Responsive

Mobile first from 360px, three breakpoints, and the exact behaviour of every 6ixstack component as the viewport grows.

Overview

6ixstack is designed for the phone first: most people check what's on tonight from transit or a hallway. Base styles target 360px; breakpoints at sm (640px), md (768px) and lg (1024px) add space and side-by-side regions. See Layout for the breakpoint tokens.

Rules

  • Use min-width queries in rem only; the few max-width: 39.99rem rules exist where hiding is simpler than revealing and are documented with their component.
  • Prefer intrinsic layouts (auto-fill grids, flex-wrap clusters) over breakpoints.
  • Filter chips and segmented controls scroll horizontally instead of wrapping to two rows.
  • Primary actions in page headers become full width on phones; the safe action sits beneath.
  • Fixed bottom elements (sticky ticket CTA, toast region) add env(safe-area-inset-bottom).
  • Full-height regions use 100dvh so mobile browser chrome does not clip them.

Touch and pointer

  • Every target is at least 24×24px; primary mobile actions (nav links in the drawer, sticky CTA, segmented items) are 44px tall.
  • @media (hover: none) shows hover-only affordances permanently, such as organizer table row actions.
  • Map dots have a 24px hit area larger than the visible dot, and every map event is also reachable from the list.
  • No interaction depends on hover: tooltips also show on focus, and the map tip opens on tap.

Accessibility

  • No orientation lock (1.3.4).
  • Reflow at 320 CSS px without two-dimensional scrolling, except data tables and the map (1.4.10).
  • Content hidden at small sizes stays available to assistive technology when it carries meaning (calendar event titles).
