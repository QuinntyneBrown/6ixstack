Theming

Light and dark from one semantic tier, OS preference by default, and a recipe for adding a theme without touching component CSS.

Overview

6ixstack ships a light and a dark theme from one set of semantic tokens. Light is the default on :root; dark applies when the page or a subtree sets data-theme="dark", or automatically when the operating system prefers dark and the page has not forced data-theme="light".

How themes work

  • Tiers. Primitives (--palette-*) hold raw values; semantic tokens (--color-*, --shadow-*) give them meaning; component tokens (--btn-bg, --alert-fg) scope them to one component. A theme overrides the semantic tier only.
  • Selection. [data-theme="dark"] and @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } } carry identical declarations, so a forced choice and the OS preference behave the same.
  • Native controls. Each theme sets color-scheme, so scrollbars, date pickers and form controls follow.
  • Preferences. prefers-contrast: more strengthens borders and muted text; forced-colors: active hands borders and the focus ring to system colours; prefers-reduced-motion zeroes durations.
  • Fixed-dark regions. The event map stays ink in both themes; it reads --color-map-*, which only changes its border and depth in dark.

How dark is built

  • Surfaces lighten as they rise: canvas < surface < raised < subtle.
  • The ink accent flips to near-white with ink text on it, so primary buttons stay the highest-contrast element.
  • Topic colours switch to the -bright set; status backgrounds become deep tints with light text.
  • The featured card stops being ink-on-canvas (which would vanish) and becomes a raised surface with a visible border.
  • Shadows get darker and stronger, but separation comes mainly from the surface steps.

Adding a theme

A partner or event-specific theme is another [data-theme] block that overrides semantic colour tokens. It must not touch primitives or component CSS.

/* tokens.css */
[data-theme="pride"] {
  --color-accent: var(--palette-gray-950);
  --color-brand: var(--palette-topic-dotnet);
  --color-fg-brand: var(--palette-topic-dotnet);
  --color-focus-ring: var(--palette-topic-dotnet);
  color-scheme: light;
}
  1. Override only --color-* (and --shadow-color if surfaces change).
  2. Add every pair the theme changes to tokens/contrast-pairs.json with "themes": ["pride"] where it differs.
  3. Run check_contrast.py tokens/tokens.css; it must exit 0.
  4. Regenerate tokens.json with tokens_to_json.py.

Consuming tokens.json

tokens/tokens.json is a DTCG export generated from tokens.css: each token has $type and $value, aliases are written as {group.token}, and dark overrides live under $extensions. The Angular front end consumes the CSS directly; other platforms (e-mail templates, the ICS feed's HTML description, native wrappers) can generate constants from the JSON with Style Dictionary or a small script.

python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css
