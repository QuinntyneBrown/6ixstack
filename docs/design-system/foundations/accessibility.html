Overview

6ixstack targets WCAG 2.2 AA. The system is accessible by construction: tokens guarantee contrast and reduced motion, components use native elements first, and every component page documents its role, keyboard model, focus, labelling, contrast, motion and touch behaviour.

Perceivable

RequirementSCRule in 6ixstack
Text contrast1.4.3Body, label and secondary text ≥ 4.5:1 on every surface; checked pairs in Color.
Non-text contrast1.4.11Input borders, focus ring, switch tracks, status icons and topic dots ≥ 3:1.
Use of colour1.4.1Status is colour + icon + text; links are underlined; topic dots sit beside topic names; required fields say “required”, optional ones “(optional)”.
Resize and reflow1.4.4, 1.4.10All sizes in rem; pages reflow at 320px; only tables and the map scroll in two dimensions.
Text spacing1.4.12Nothing clips with increased line, paragraph, letter and word spacing.
Images and maps1.1.1The event map is role="img" with a summary label and every event duplicated in the list; decorative SVGs are aria-hidden; icon-only buttons have aria-label.
Orientation and motion1.3.4, 2.3.3No orientation lock; tokens zero durations under reduced motion.
Input purpose1.3.5autocomplete on name, e-mail and URL fields in contact, sign-in, settings and submit-event.

Operable

RequirementSCRule in 6ixstack
Keyboard2.1.1, 2.1.2Everything works with Tab, Enter, Space and arrows where the pattern says so; only dialogs trap focus and Escape releases them.
Focus visible2.4.7, 2.4.11One orange ring, --focus-ring-width wide with --focus-ring-offset, on :focus-visible; ≥ 3:1 against canvas and surface.
Focus not obscured2.4.11The sticky header sets scroll-padding-top; toasts never cover the focused element.
Focus order2.4.3DOM order is visual order (the map is placed first on phones in the DOM too); no positive tabindex; dialogs return focus to their trigger.
Target size2.5.8Every target ≥ --target-min; primary mobile targets ≥ --target-comfortable.
Dragging2.5.7The map can be explored with buttons (day timeline, zoom) and the list; nothing requires a drag.
Timing2.2.1, 2.2.2Toasts last at least 8 s and pause on hover and focus; error toasts persist; the map timeline can be paused.
Bypass blocks2.4.1A skip link to #main on every page; landmarks header, nav, main, footer.
Titles and headings2.4.2, 2.4.6Unique titles (“Azure Data & AI Day GTA · 6ixstack”), one h1, headings in order.
Link purpose2.4.4“Get tickets · $49”, “View Toronto .NET User Group”; never “click here”.
Pointer cancellation2.5.2Actions fire on click, never on pointer down.

Understandable

RequirementSCRule in 6ixstack
Labels3.3.2Visible label for every control; placeholders are examples only.
Errors3.3.1, 3.3.3Messages name the field and the fix (“Enter an email address like name@example.com”); aria-invalid + aria-describedby; an error summary (“Fix 2 things before sending”) links to each field and receives focus on submit.
Error prevention3.3.4Cancelling an event, rejecting a submission and deleting an account are confirmed in a dialog that names the consequence.
Redundant entry3.3.7Editing an event pre-fills every field; the organizer's community is pre-selected.
Accessible authentication3.3.8Sign-in by e-mail link or password with paste and password managers allowed; no puzzles.
Consistency3.2.3, 3.2.4Header, nav order and icon meanings are identical on every page.
On input3.2.2Changing a filter or select updates results in place and announces the count; it never navigates.
Help3.2.6Contact and code of conduct links sit in the footer on every page.
Language3.1.1lang="en" on every page; lang on non-English event titles.

Component contract

Every component page's Accessibility section contains:

  1. Role and pattern, with a link to the WAI-ARIA Authoring Practices pattern.
  2. Keyboard map: keys and effects.
  3. Focus: where it starts, where it returns, how the ring looks.
  4. Labelling: what is labelled and how, and what is announced.
  5. Contrast: the token pairs with live ratios in both themes.
  6. Motion: what animates and what reduced motion does.
  7. Touch: target sizes and hover alternatives.

Testing

  • check_contrast.py for every declared pair, both themes.
  • check_design_system.py and the mocks checker for labels, names, alt text, landmarks, headings and links.
  • Manual each release: tab through the events home, an event detail, submit-event and one dialog; use NVDA or VoiceOver on the submit form, the share dialog and the organizer table; zoom to 200% and 400%; emulate reduced motion and forced colours.
  • Playwright acceptance tests assert accessible names and roles through page objects.
