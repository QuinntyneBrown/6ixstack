Pattern

Empty and error states

What 6ixstack shows when there is nothing to show: first run, no results, all caught up, no permission, and failures at region and page level.

Overview

An empty region is a chance to say what normally lives there and how to get it. 6ixstack separates four reasons a region can be empty, because each needs different words and a different action: nothing exists yet (first run), filters hide everything (no results), the person cannot see it (permission) or loading failed (error). Whole-page failures use an error page (404, 403, 500, offline) that keeps the site header and footer.

Responsive

  • Empty states centre in their region at every width; padding drops from --space-12 to --space-8 with .empty--compact inside cards and dialogs.
  • .empty__actions wrap; on phones the primary button sits first and both buttons can take the full row.
  • Error pages keep the site header and footer; the status code shrinks with --font-size-hero (clamped 48–72px).

Accessibility

The empty icon is decorative (aria-hidden); the title carries the meaning. When an empty state replaces results after filtering, announce the count in the results line (“0 events”) through the existing polite live region rather than moving focus. Error regions use role="alert" once when they appear. Error pages set a unique <title> (“Page not found — 6ixstack”) and keep a single h1; the large status code is aria-hidden so it is not read before the heading.
