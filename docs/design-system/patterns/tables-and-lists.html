Data tables and lists

How 6ixstack lays out collections: day-grouped event lists, card lists, the organizer table, sorting, status, row actions and load more.

Overview

6ixstack shows collections three ways. Event lists group event rows under day headings, because people scan by date. Card lists (directory cards, review cards) are for items with several actions or rich metadata. Tables appear only in the organizer dashboard, where people compare a few columns across their own events. Lists use “Show more” with a count rather than numbered pages; numbered pagination is reserved for archives.

Responsive

  • Event rows stack time above the title below sm; price and going move under the metadata.
  • Directory cards use .card-grid (auto-fill, 18rem minimum): one column on phones, up to three on desktop.
  • The dashboard table scrolls horizontally inside .table-wrap on phones; it has five columns, so it does not collapse to cards.
  • On the events page the list and the map stack (map first) below lg and sit side by side above it.

Accessibility

Structure

Lists are <ul>; each day group is a <section aria-labelledby> with its date heading; each event is an <article> whose title is the only link. Tables have a <caption>, scope="col" headers and aria-sort on the sorted column, whose header contains a real button.

Keyboard

KeyAction
TabMoves through each item's title link, then its actions.
EnterOpens the item, or sorts when on a column header button.
SpaceActivates Show more and row action buttons.

Labelling

Repeated row actions include the object in visually hidden text (“Cancel …Azure Data & AI Day GTA”). Counts carry meaning in their label: aria-label="142 going". After Show more, focus stays on the button and the new count is announced politely.

Content

  • Day headings: weekday, then date in muted text — “Tuesday November 3”. No year unless the list crosses one.
  • Times: “6:00 PM” in Toronto time; a stream adds the source time beneath (“9:00 AM PT”).
  • Counts are exact and plain: “142”, “1,204 people”, “Showing 14 of 61 events through December 31”.
  • Missing values are an em dash in tables (—), never “N/A” or empty.
  • Status labels are adjectives or short states: Published, In review, Needs changes, Cancelled, Past, Draft.

Do and don't

Sources

  • pages/events/default — day groups, event rows
  • pages/events/long — load more
  • pages/events/day-focus — dimmed groups
  • pages/organizer-dashboard/default — table, status
  • pages/review-queue/default — review cards
  • pages/communities/default — directory cards
  • pages/organizer-dashboard/loading — skeleton rows

Drift fixed during extraction: the dashboard table sets white-space: nowrap inline on date and action cells in every row; the system keeps it inline (it is a per-column decision) but notes that a .nowrap utility would remove the repetition. One review card in the mock carries data-state="hover" in the default state; it is documentation of hover, not a selected state.
